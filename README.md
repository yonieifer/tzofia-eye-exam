# tzofia-eye-exam

## database
הבחירה במונגו היא מטעמי נוחות בלבד - המידע שהמבחן דורש הוא לא באובייקטים או מערכים מקוננים ולא נצרך כאן שום מפתח זר או קישוריות לטבלה אחרת, וגם הסכמה היא קשיחה.
 בגלל קשיחות הסכמה גם השתמשתי במונגוס ולא בדרייבר הנייטיב של מונגו מכיון שמונגוס מאפשר לבנות מודל על פי סכמה - אבל מבחינת התאמה DB SQL כמו supabase  יכול להתאים כאן יותר. הסיבה לבחירה במונגו כמו שציינתי היא מטעמי נוחות בלבד כיון שאני רגיל יותר לזה וזה ייקח לי פחות זמן ולכן אם ישאר לי זמן אני יחליף את הדאטה בייס.

## validation
השתמשתי בZOD לוולידציה לשל הקלט הנכנס בגוף הבקשה שעושה ולידציה על השדות גם על הטייפים ואם נצרך גם ENUM הוא מוודא שזה קלט מאושר על פי הסכמה - אם לא נזרקת שגיאה.

## error handling
ההנדלר בודק אם זה שגיאות שהשרת העלה בכוונה א ושגיאות ולידציה וכו' שאני מעוניין שהלקוח ייראה ואם כן הוא מחזיר הודעה רלוונטית עם סטטוסים כדלהלן, אחרת הוא מדפיס את השגיאה לקונסול ושולח הודעת שגיאה פנימית בשרת עם סטטוס 500.
שאר הסטטוסים הם:
* 200 - בהצלחה
* 201 - נוצר בהצלחה
* 400 - בקשה לא קליטה
* 409 - שגיאת ולידציה
